The soundness defect this closure had to fix first
--------------------------------------------------
`cell_level_compare` iterated `generate_cell_names(cell_range)`, which is **empty** for `'Sheet1'!BD2:308`
because `parse_cell_range` gives an end column of 0, so the loop body never ran and the function returned
`True`. The parent reproduced it with two authored workbooks whose only real cell differs
(`golden A1=5`, `result A1=999`), in this checkout:

    $ python3 -c "..."
    generate_cell_names('BD2:308') -> []
    compare_workbooks(..., "'Sheet1'!BD2:308") -> ok=True  msg=''
    compare_workbooks(..., "'Sheet1'!A1")      -> ok=False msg='value difference at A1: golden has 5, result has 999'

So a released row whose `answer_position` had a range end without column letters scored **1.0 for any
submission** and was recorded as a measured pass. `w-spreadelig` had already classified released row `73-45`
as `not_gradable_as_installed` for exactly this reason and flagged `130-9` as the
quoted-sheet-name-with-commas variant. The fix makes an empty expansion exit 3 with a named reason and no
reward file, and names an unaddressable component instead of skipping it; the released colon-range parser
`ValueError` stays a measured zero exactly as before.
