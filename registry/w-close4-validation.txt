Parent closure of a fourth blocker under operator decision (A), and the first applied to a
`measurement-coverage` blocker rather than a `dataset-journal-gap`.

Decision
--------
The parent filed `hotpotqa / historical-comparison-receipts` as a **closure candidate** with its
clause-by-clause basis in `registry/blocker-closure-assessment.md` - because it is the first application
of reading (A) outside the journal-coverage family, and because the earlier assessment had deliberately
left it open. The operator then confirmed the closure. Reading (A) is unchanged: the diagnostic-time
clauses are preconditions on a *future, separately authorized* diagnostic rather than conditions on
closure. The controlling argument is the operator's own standing rule - a requirement that is **proven
unobtainable is withdrawn and recorded as a limit rather than left open** - so leaving this blocker open
would reimpose, as an open blocker, a requirement the registry had already withdrawn.

Closed
------
* `hotpotqa / historical-comparison-receipts`, removed from `registry/dataset-blockers.json`.

The guard change is a move, not a deletion
------------------------------------------
`tests/quality/test_measurement_coverage_hg_b3.py:151-215` previously parametrized hotpotqa with
`active_id="historical-comparison-receipts"` and asserted the blocker **exists** with status
`measurement`, that its evidence cites the timeout-closure record, that `schema-timeout-measurement` is
absent, and that its `shared_blockers` set tracks the live shared set. hotpotqa now takes the test's
`withdrawn` branch beside `bird_minidev` and `ds1000`, with new assertions over its own withdrawal entry:

* `**Searched:**` is present (as for the other two);
* `**local pilot of this platform**`, `the receipts existed and were`, `lost, rather than never being
  captured` - the wording that distinguishes this case from the never-captured pair, where "not
  published upstream" would have overstated it;
* `hotpotqa-h0-10pct-v4`, `historical_runs` keeps `run_id=null` and `effect=null`, and the enumerated run
  directory `/tmp/harnessgrad-runs/hotpotqa-h0-10pct-v4`.

The `historical_runs` baseline comparison, the live-`shared_blockers` comparison and the timeout-closure
citation all still run against the cleared dataset; the citation is now read from the closure record,
which carries the exact `path`/`locator` pair verbatim. Nothing was deleted to make the closure pass.

`registry/withdrawn-requirements.md` keeps its dated text and gains a **Superseded 2026-10-15** sentence
pointing at the closure note, so the entry no longer reads as "an active blocker that stays open".

What this does NOT do
---------------------
It closes no measurement and asserts no score. The v4 run stays incomplete with `effect=null`, the
94/1382/1476 coverage stays unverified and unbound, unknown outcomes stay unmeasured and never become
zeros, and every diagnostic-time clause remains a requirement of any future diagnostic - which still
needs its own authorization, a fresh run ID, a split/side binding and the staged pilot policy. The
pre-closure text remains readable in the git history of `registry/dataset-blockers.json`.
