**One platform choice, reported six times in the intern/handoff:** `--trials N` averages a task’s measured trial scores, then the declared run policy averages measured task scores (`eval/run/runner.py:1350-1375`; `data/aggregation_policies.json:2-32`; `eval/run/metrics.py:43-44`). It does not select a verifier-best sample for test@N, estimate pass@k for k>1, or require k successes for pass^k. For n sampled attempts with c successes, mean c/n estimates pass@1; success-at-least-once and all-k-success are different statistics. At k=1 some binary definitions coincide, but protocol/split/budget still matter. The handoff explicitly maps the six repeats to GSM8K, MuSiQue, 2Wiki, τ-bench, Reasoning Gym and BIRD (`registry/w-evidence-external-sources.md:1317`). The mapping is inherited from that retrieved audit; it does not establish that every named paper uses the same pass statistic (Reasoning Gym’s aggregate remains unconfirmed). It is one aggregation decision, not six independent scorer bugs. GSM8K documents the test@N difference (`data/datasets/gsm8k.py:37-38`); LiveCodeBench explicitly limits each check to one generation (`data/datasets/livecodebench/verify/check.py:28-30`). Repeated trials also do not implement a three-distinct-workbook or multi-task-scenario aggregate.
