# HarnessGrad Agent Operating Rules

## Execution priorities

1. Close automatically solvable blockers and internalize reusable platform capabilities before launching large pilots.
2. Use isolated Codex worktrees only. Parent reviews every diff, runs focused tests, rejects stale reports and unrelated changes, then merges safe commits and updates the journal.
3. Keep up to 10 independent Codex tasks active when work can be parallelized. Every task must have a unique output filename; never trust inherited `reports/report.md` without checking the diff and commit.
4. Avoid idle rounds: combine waits with concrete receipt inspection, diff review, test execution, journal work or launch preparation. Do not spend a round only polling unchanged status.

## Working copies

There are exactly **two writers**, and the rule is about who yields to whom:

- **The operator writes directly to the main checkout** `/mnt/20t/xubuqiang/Study/HarnessGrad`
  whenever they want. That is supported, not a conflict. An agent merges **on top of** whatever
  it finds there and never rewrites, rebases away, reverts or moves an operator commit. When a
  merge conflicts because the operator changed the same file, the operator's change is the
  starting point and the agent's is the one that has to fit around it.
- **Agents never commit to `main`.** They work in registered `git worktree` checkouts under
  `/tmp/hg-*`, commit there, and the parent reviews the diff and merges.
- Every *other* copy of this repository on this machine is read-only or disposable.
- **Never create a full clone of this repository inside `Study/`.** Two were made on 2026-11-17
  (`HarnessGrad-appworld-controls-20261117`, `HarnessGrad-gaia-controls-20261117`). Both are now
  stranded on pre-rewrite commits that do not exist in `main`'s object store, and both still
  carry the old layout (`web/dist`, root-level report files). Their `origin` remotes -- which
  pointed at the main checkout, fetch **and push** -- have been removed, because a single
  `git push --force` from either would have restored the old history over `main`.
- They are kept, not deleted, and not reset: they hold run receipts and evidence
  (`gaia-evidence/`, `gaia-evidence-all17/`, `GAIA_FINAL_LAUNCH_RECEIPT.json`, the appworld
  `deliverables/` and `runtime/`) that exist nowhere else, and rule 5 of the staged pilot policy
  says old and incomplete receipts are preserved. Treat them as frozen evidence: read them, never
  fetch, merge, push or "update" them.

  explicitly before deleting any, since they are the only record of that codex work.

## Test execution

Pytest `--basetemp` must be **OUTSIDE the platform tree**, for example
`--basetemp=/tmp/harnessgrad-pytest-quality`. Driver-based tests use `tmp_path`
as a harness work root, which the runner correctly refuses inside the platform.
Omitting the option preserves pytest's normal default.

## GPU execution

- **One local endpoint: `http://127.0.0.1:8002/v1`** (model `qwen3.5-9b-local`). GPU0 and the
  `8001` server were released on 2026-10-14 to give a card back; do not start a second one.
- `eval/unix_model_relay.py` hard-codes the agent model route to `127.0.0.1:8002`, so `8002` is
  the endpoint a containerised harness actually reaches. That, not preference, is why this is
  the one that was kept -- the other would have needed a production change.
- Keep the endpoint productively occupied with necessary no-model controls, diagnostics or valid
  pilots; never create duplicate, fake or scientifically unjustified work for utilization. If
  there is no approved diagnostic or pilot, an idle loaded server is the correct state: record
  that rather than inventing work.
- Bind each run to one endpoint and one fresh run ID. Keep total H0 concurrency `<=3`, `jobs=1`.

## Staged pilot policy

- First run a one-task/one-trial diagnostic after all dataset gates pass.
- For temporary reruns of blocked/incomplete datasets, select `min(30, ceil(10% * eligible))` tasks before execution, with `trials=1`, `jobs=1`.
- Expand only after a separate review of a valid measured diagnostic receipt. Do not silently revert to the historical `min(50, ceil(10% * eligible)) x 3` protocol.
- Invalid, unmeasured, timeout, scorer, provider, cleanup or snapshot failures are not ordinary zero scores.
- Preserve old and incomplete receipts; never resume or overwrite an old run ID.

## Dataset taxonomy

Task capability is a cross-table: `demand x surface`. Harness coverage is a separate axis: `exercises`. Do not collapse these into one flat dataset category.

## Prohibited shortcuts

No method tuning, paid endpoints, heldout leakage, SOTUQA, API-Bank, NESTFUL, Tau2-bench, Matrix, score fabrication or fake benchmark utilization.

## Evidence requirements

Every diagnostic or pilot records metric identity, eligible/selected/task/trial coverage, invalid and unmeasured counts, source/split/manifest/model/harness hashes, endpoint binding, resource/budget limits, cleanup receipt and comparability notes.

## Blocker closure priorities

Prioritize selected-only/privacy and provenance, scorer dependency/network and offline closure, trusted verifier/runtime, artifact-only state export, filesystem quota enforcement, official scorer execution, snapshot lifecycle and cleanup. ## Correcting the sweep: batches that hit their timeout produce spurious failures

Three of the sweep's batches exited `rc=124`, meaning the 240 s per-batch timeout killed pytest rather
than pytest finishing. Failures reported from those batches are **not** reliable: the in-flight tests
are disrupted and appear in the summary.

from batch 12, 36 or 72 until it is re-run alone.

## The B5 body restoration invalidates any dataset run that is executing while it writes

The B5 replay writes bodies into the tracked tree (`tests/fixtures/external_provenance_b5/responses/*.body`).
`driver.py`'s run-integrity check hashes protected paths around every method call, so a replay that
writes during a run makes the run fail **correctly**:

```
FAILING RUN: protected files changed during method call:
  tests/fixtures/external_provenance_b5/responses/bfcl-blob-multi_turn_checker.body
PlatformTampered: {'added': [...], 'removed': [], 'modified': []}
```

Measured consequence, 2026-10-15: with the replay running, `test_dgm_rule.py::test_a_batch_becomes_one_curve_point_per_child`
failed with `driver exited 3` and `test_candidate_apply.py::test_a_half_finished_step_is_not_a_measurement`
failed with `"step failed" not in combined`, and `test_isolation.py`'s autouse
`_the_shared_checkout_is_never_edited` teardown raised `added: [...bfcl-blob-model_config.body]`. All three
pass once the replay is stopped, so none of them is a code defect. The replay also explains at least one
earlier sweep failure (`test_stop_semantics.py`, 1 failed in the sweep, **4 passed** run alone with the
replay stopped) and is a plausible contributor to others.

**Rule for this tree:** do not run the B5 replay concurrently with pytest or with any dataset run. The
replay is left **paused** (`kill -STOP`) rather than killed, so its 71 remaining bodies can be resumed with
`kill -CONT` when nothing else is executing; the residue and its per-body reasons are enumerated in
`reports/w-b5restore-replay2-20261015.jsonl`.

# w-metriccmp: local versus upstream metric comparability

dataset answers or observed executions. The proposal chooses separate reporting for

for StrategyQA. No blocker is closed and no execution is authorized.

## Evidence scope and common local processing

**FOUND:** retained upstream source views were retrieved from local Git objects and
copied unchanged into `registry/w-metriccmp-sources/`. The exact `git show` commands
and observed outputs are in `registry/w-metriccmp-validation.txt`. Original Git
locations, observed source-view sizes/digests, and recorded upstream revision URLs
are in `registry/w-metriccmp-sources/provenance.json:3`, `:13`, `:23`, `:34`, `:45`
and `:53`. These are readable comparison sources, not runtime imports or new

(`registry/w-metriccmp-sources/provenance.json:41`). Installed custody and row/task

**ABSENT, bounded scope:** the worktree directories `tests/fixtures/hg_e1_review`,
`tests/fixtures/hg_wprov`, and `tests/fixtures/hg_wjc2` were absent at initial
inspection. Only the ignored `hg_wprov/README.md` was subsequently restored

For all three text QA adapters, the effective local input includes shared processing.
The plain `answer.txt` route unwraps **one** matching pair of single quotes, double
quotes or backticks, then strips surrounding whitespace. The optional validated
`prediction.json` route uses its `answer` string directly; it bypasses this unwrap.
Decisive lines (`data/scaffolds/qa/verify/check.py:132`, `:135`, `:251`):

```python
_QUOTED = re.compile(r"^\s*(?P<q>['\"`])(?P<body>.*)(?P=q)\s*$", re.S)
def unwrap(answer: str) -> str:
    match = _QUOTED.match(answer)
    return match.group("body") if match else answer
    prediction = (str(structured["answer"]) if structured is not None
                  else unwrap(answer).strip())
```

The scorer receives that prediction and the trusted gold
(`data/scaffolds/qa/verify/check.py:254-260`). An absent answer file supplies `""`
(`:194`); unreadable input, invalid structured predictions and scorer exceptions
are unmeasured (`:195-197`, `:203-219`, `:261-265`). Those conditions do not become
ordinary wrong-answer zeros.

**Common aggregation, applicable to each dataset below:** trials of the **same
task** are averaged, then measured task means receive equal weight. Decisive lines:
`scores = [_score_of(res) for res in measured]`,
`score = sum(scores) / len(scores)`, `per_task[tid] = score`
(`eval/run/runner.py:1225-1232`). An unmeasured trial makes the runner return the
