    8 Where the tasks come from
    9 -------------------------
   10 `alfworld/alfworld`, the `valid_unseen` split of the `json_2.1.1` data. That is the
   11 split ALFWorld's own paper evaluates out-of-distribution on, and it is what a score
   12 here should be compared with. The task list is **not** this adapter's invention: it is
   13 the same filter `alfworld/agents/environment/alfred_tw_env.py:collect_game_files`
   14 applies -- a trial directory must have both `traj_data.json` and `game.tw-pddl`, must

   16 carry `solvable: true`. Measured over the extracted data: 134 trials pass, which is
   17 ALFWorld's own `Evaluating with 134 games`.
   18 
   19 The three provisioning traps, each verified rather than repeated
   20 ---------------------------------------------------------------
   21 1. **The data is in GitHub release assets, not in the repository and not on Hugging
   22    Face.** The filenames and the release tags come from ALFWorld's own
   23    `scripts/alfworld-download`; `downloads()` below names them with the tags pinned.
   24 2. **`solvable` lives only in `game.tw-pddl`, which ships in the `0.4.2` asset**
   25    (`json_2.1.3_tw-pddl.zip`). Verified: `json_2.1.1_json.zip` contains only
   26    `traj_data.json` (7302 of them) and `json_2.1.1_pddl.zip` only `initial_state.pddl`
   27    (7080); neither contains a `game.tw-pddl`. Without that key
   28    `collect_game_files` skips **every** trial and the dataset loads as empty.
   29    Measured nuance: because the `0.4.2` game file embeds `pddl_problem` and `grammar`,
   30    the `json_2.1.1_pddl.zip` archive is *not* read by the loading path -- it is read by
   31    ALFWorld's generation path (`alfworld-generate`). `downloads()` still names all
   32    three, because `alfworld-download` fetches all three and a regeneration needs it.
   33 3. **The PDDL domain and the TextWorld grammar are in the repository's Python package,
   34    not in any data pack.** Verified location:
   35    `alfworld/data/alfred.pddl` and `alfworld/data/alfred.twl2` -- i.e.
   36    `_src/repo/alfworld/data/` in the checkout this adapter was validated against, and
   37    `site-packages/alfworld/data/` in an install. ALFWorld's own
   38    `scripts/alfworld-download` copies them from the *installed package* into
   39    `$ALFWORLD_DATA/logic/`, which is what `base_config.yaml` and `eval_config.yaml`
   40    point `logic.domain`/`logic.grammar` at. The symptom of a missing one depends on
   41    where you enter: pointing TextWorld at a `.pddl` (or extensionless) file gives
   42    `ValueError: Unsupported game format`, while an empty grammar gives a bare
   43    `StopIteration` and a missing `--domain` gives `FileNotFoundError` -- none of which
   44    names the real cause. Our loading path does not need them (the game file is
   45    self-contained), and the adapter does not depend on the `logic/` copy; it is
   46    provisioned because ALFWorld's own tooling expects it.
   47 
   48 How ALFWorld fits the platform's one-shot contract
   49 --------------------------------------------------
   50 ALFWorld is interactive and multi-turn; the platform grades what a harness *left
   51 behind*. The tau-bench pattern resolves that: the agent acts through a CLI
   52 (`data/datasets/alfworld/cli/alf`), the CLI appends every action to `alf_actions.jsonl`, and
   53 `data/datasets/alfworld/verify/check.py` replays that log in a freshly built environment and
   54 reads TextWorld's own `won` flag. The CLI's observations, its summary and any `won` it
   55 prints are never consulted -- the log holds actions and actions are re-executed.
   56 
   57 The environment is `kind: "files"`, not a container. That is forced by a hard constraint
   58 of this exercise (`Do NOT use Docker`) and it is the reason this dataset works on a
   59 host with nothing but `pip install alfworld textworld`: the CLI and the check both run
   60 under the platform's Python. The consequence is stated loudly in
   61 `docs/dataset-onboarding-skill.md`: a `files` environment cannot declare a longer
   62 `agent_timeout_s`, and the platform's `reward_file`/`evidence_file` channels were
   63 container-only before this dataset (`eval/verification/verifier.py::_verify` now honours them for a
   64 host check as well -- the smallest change that let a no-Docker dataset keep the
   65 contract's evidence channel).
   66 
   67 The metric, and what is deliberately not added
   68 ----------------------------------------------
   69 `reward = 1` iff the replayed episode reports `won` at some step inside `STEP_BUDGET`
   70 actions. This is ALFWorld's own metric (`evaluate_dagger` takes the maximum of the
   71 per-step `won`). `alf done` exists in the CLI -- the harness needs a way to stop -- but
   72 the check does **not** require it: ALFWorld has no such requirement, and tau-bench's
   73 `done` gate exists only because tau-bench computes a reward only for a finished
   74 episode. Adding one here would be inventing a requirement the benchmark does not have.
   75 
   76 The split
   77 ---------
   78 The benchmark's own evaluation split is *all* of `valid_unseen` and it declares no
   79 train/eval division. The platform needs one, so it is **imposed here**, derived from the
   80 task id by hash so that adding or removing a task does not reshuffle the other side
   81 (`_is_eval`, the same rule `data/datasets/terminal_bench.py` uses). A score on the eval side is
   82 a score on about a third of `valid_unseen`, not on the benchmark; `HG_ALFWORLD_SPLIT=none`
   83 runs every task as eval and accepts the driver's warning.
   84 
   85 Noise, before anyone compares two ALFWorld runs
   86 -----------------------------------------------
   87 Measured on this machine with `qwen3.5-9b-local`, the same arm, the same 20 tasks, the
   88 same seed and temperature 0, over five batches: **10 / 8 / 11 / 11 / 11 tasks, SD 1.30
   89 tasks = 6.5 percentage points, 4 of 20 tasks changed side at least once.** A move smaller
   90 than roughly 6 points on 20 tasks is the noise. The full note is in
   91 `docs/experiment_noise.md`; quote the task count with every ALFWorld number, because the
   92 granularity is `1/n`.

  200 def _collect() -> list[dict]:
  201     """Every runnable game in the split, filtered exactly as ALFWorld filters them.
  202 
  203     The filter is `AlfredTWEnv.collect_game_files`, reproduced rather than called:
  204     calling it would drag in `textworld` and crawl the whole data tree at import time,
  205     and the adapter must be importable on a machine that has not provisioned the data
  206     (see `published()` in `data/scaffolds/registry.py`: a module that will not import is hidden
  207     from the chooser). The rules, in the same order upstream applies them:
  208 
  209       * a trial directory must hold `traj_data.json` and `game.tw-pddl`;
  210       * its path must not contain `movable` or `Sliced` (unsupported trajectories);
  211       * `traj_data.json`'s `task_type` must be one ALFWorld evaluates;
  212       * `game.tw-pddl` must carry `solvable` and it must be true.
  213 
  214     Each returned record is everything the adapter needs and nothing it does not.
  215     """
  216     root = _split_dir()
  217     records: list[dict] = []
  218     for game_path in sorted(root.glob("*/*/game.tw-pddl")):
  219         trial_dir = game_path.parent
  220         task_dir = trial_dir.parent
  221         label = f"{task_dir.name}/{trial_dir.name}"
  222         if "movable" in str(trial_dir) or "Sliced" in str(trial_dir):
  223             continue
  224         traj_path = trial_dir / "traj_data.json"
  225         if not traj_path.is_file():
  226             continue
  227         try:
  228             traj_data = json.loads(traj_path.read_text())
  229             gamedata = json.loads(game_path.read_text())
  230         except (OSError, ValueError) as exc:
  231             raise ValueError(f"alfworld: {label} is unreadable: {exc}") from exc
  232         if traj_data.get("task_type") not in TASK_TYPES.values():
  233             continue
  234         if "solvable" not in gamedata:
  235             # The 0.4.2 asset is the only one with this key; an extraction that skipped
  236             # it lands here for every trial. Say that rather than "0 tasks".
  237             raise ValueError(
  238                 f"alfworld: {label} has no `solvable` key -- the game files are not the "
  239                 f"0.4.2 `json_2.1.3_tw-pddl.zip` ones. See downloads() and "
  240                 f"tools/datasets.py --check")
  241         if not gamedata["solvable"]:
  242             continue
  243         match = _GOAL_RE.search(str(gamedata.get("grammar") or ""))
  244         if not match:
  245             raise ValueError(
  246                 f"alfworld: {label}: the game grammar has no `task` rule, so the "
  247                 f"goal text cannot be read")
  248         goal = json.loads('"' + match.group(1) + '"')
  249         records.append({
  250             # The official per-game label is the last two path components
  251             # (`evaluate_dagger` prints `"/".join(game_names[i].split("/")[-3:-1])`).
  252             # A slash is not safe in a platform task id (it becomes a container name
  253             # and a path component), so it is spelled `__` here.
  254             "task_id": f"{task_dir.name}__{trial_dir.name}",
  255             "label": label,
  256             "task_type": traj_data["task_type"],
  257             "goal": goal,
  258             "game_path": game_path,
  259             "stripped_game": _stripped_game(gamedata),
  260         })
  261     return records
  262

  264 def _stripped_game(gamedata: dict) -> str:
  265     """The game file without the reference solution, as JSON text.
  266 
  267     Kept as a string because that is the shape `SETUP`/`VERIFY.inputs` take for inline
  268     content, and because it means the stripped copy is built once at import instead of
  269     being written somewhere on disk that could drift from its source.
  270     """
  271     clean = {k: v for k, v in gamedata.items() if k != _LEAKED_FIELD}
  272     return json.dumps(clean)

  275 def _goal(record: dict) -> str:
  276     """The instruction, with a preamble that names only the interface.
  277 
  278     Nothing here hints at the solution. It states the goal the environment will check,
  279     how to act, and the budget -- the three things the agent cannot discover from the
  280     interface alone.
  281     """
  282     return (
  283         f"# Task\n"
  284         f"\n"
  285         f"You are in a text-based house, described one room at a time, and you act by\n"
  286         f"typing commands. The game is `{GAME_IN_WORKDIR}` in your working directory.\n"
  287         f"\n"
  288         f"**{record['goal']}**\n"
  289         f"\n"
  290         f"## How to act\n"
  291         f"\n"
  292         f"- Look at where you are and what you may do:\n"
  293         f"      python3 alf look\n"
  294         f"- Take one action (it must be one of the admissible actions `alf look`\n"
  295         f"  prints; quote it):\n"
  296         f"      python3 alf do \"go to desk 2\"\n"
  297         f"- When the task is finished, say so:\n"
  298         f"      python3 alf done\n"
  299         f"- Every action is appended to `{LOG_IN_WORKDIR}` and costs one of your\n"
  300         f"  **{STEP_BUDGET}** steps. A step that TextWorld does not understand still\n"
  301         f"  costs a step.\n"
  302         f"\n"
  303         f"## How it is scored\n"
  304         f"\n"
  305         f"- Your actions are replayed from the beginning in a fresh environment, and the\n"
  306         f"  task counts as solved only if the environment's own goal check reports the\n"
  307         f"  goal satisfied within the {STEP_BUDGET}-step budget. There is no judge and\n"
  308         f"  no partial credit.\n"
  309         f"- Nothing you print is read. Only the actions you take are.\n"
  310     )

  327 def _verifier(record: dict) -> dict:
  328     """The grade: the check, its trusted game, and where the verdict goes.
  329 
  330     `inputs` use `path` (relative to the workdir), not `dst`: on a `files` environment
  331     the platform materialises these into the workdir, and `dst` is a container path.
  332     The check, the game and the environment library are re-materialised at verification
  333     time, so nothing the agent wrote to any of them is what runs.
  334 
  335     `reward_file`/`evidence_file` are absolute in-environment paths -- the container
  336     contract. On a `files` environment `eval/verification/verifier.py` resolves them against the
  337     workdir, and the `argv` flags below write to that same resolved location. Note the
  338     **top-level-in-the-container** rule from `data/datasets/tau_bench.py:_verifier` does not
  339     apply here (there is no `docker cp`), but the paths are kept absolute anyway so the
  340     adapter is a valid container dataset if one is ever built.
  341     """
  342     return {
  343         "kind": "command",
  344         "argv": [
  345             "python3", "check.py",
  346             "--workdir", ".",
  347             "--game", GAME_IN_WORKDIR,
  348             "--log", LOG_IN_WORKDIR,
  349             "--reward-file", REWARD_REL,
  350             "--evidence-file", EVIDENCE_REL,
  351             "--budget", str(STEP_BUDGET),
  352         ],
  353         "inputs": [
  354             {"path": "check.py", "from": str(VERIFY_DIR / "check.py")},
  355             {"path": "gym_env.py", "from": str(LIB_DIR / "gym_env.py")},
  356             {"path": GAME_IN_WORKDIR, "content": record["stripped_game"]},
  357         ],
  358         "reward_file": REWARD_FILE,
  359         "evidence_file": EVIDENCE_FILE,
  360         "timeout_s": 300,
  361     }

  459 def provision_status() -> dict:
  460     """What is present locally, for `tools/datasets.py --check`.
  461 
  462     Deliberately does not import `textworld` or build an environment: this is the
  463     answer to "did the provisioning run", which has to work on a machine where it did
  464     not.
  465     """
  466     split = _split_dir()
  467     games = sorted(split.glob("*/*/game.tw-pddl")) if split.is_dir() else []
  468     solvable = 0
  469     for game in games:
  470         try:
  471             if "solvable" in json.loads(game.read_text()):
  472                 solvable += 1
  473         except (OSError, ValueError):
  474             continue
  475     logic = DATASET_ROOT / "logic"
  476     return {
  477         "root": str(DATASET_ROOT),
  478         "present": bool(games),
  479         "split_dir": str(split),
  480         "game_files": len(games),
  481         "with_solvable": solvable,
  482         "logic_files": sorted(p.name for p in logic.glob("*")) if logic.is_dir() else [],
  483         "tasks": len(_RECORDS),
  484     }

  487 #: Read once at import. `load()` is called more than once per run and the content is
  488 #: immutable. A missing data root is **not** an import failure: `published()` catches
  489 #: exceptions and hides a module that will not import, and a dataset that cannot be
  490 #: seen in the chooser before its data is provisioned is a dataset a reader cannot
  491 #: find the instructions for. `_LOAD_ERROR` carries the reason into `load()`.
  492 try:
  493     _RECORDS: list[dict] = _collect()
  494     _LOAD_ERROR: str | None = None
  495 except Exception as _exc:  # noqa: BLE001 - reported by load(), which is where it bites
  496     _RECORDS = []
  497     _LOAD_ERROR = f"{type(_exc).__name__}: {_exc}"

  500 def load() -> tuple[list[dict], dict[str, str]]:
  501     """`(tasks, scorable)`. Every task is graded by its `VERIFY` entry, so the
  502     `scorable` map is present only because the interface asks for it."""
  503     if _LOAD_ERROR is not None:
  504         raise ValueError(f"alfworld: cannot read {_split_dir()} ({_LOAD_ERROR}). "
  505                          f"Provision it with `python3 tools/datasets.py --list`.")
  506     if not _RECORDS:
  507         raise ValueError(
  508             f"alfworld: no runnable game under {_split_dir()}. The usual cause is the "
  509             f"0.4.2 `json_2.1.3_tw-pddl.zip` not being extracted, which leaves every "
  510             f"trial without `game.tw-pddl`. See downloads() and "
  511             f"`python3 tools/datasets.py --check`.")
  512     tasks = [{"task_id": r["task_id"], "goal": _goal(r), "inputs": []}
  513              for r in _RECORDS]
  514     return tasks, {r["task_id"]: "" for r in _RECORDS}

  517 def _is_eval(task_id: str) -> bool:
  518     """A deterministic third, by hash of the task id.
  519 
  520     Hashed rather than sliced off the sorted list so that adding or removing a task
  521     does not reshuffle which side every other task is on -- a split that moves under
  522     the benchmark is a split whose past scores cannot be compared with its future ones.
  523     """
  524     return hashlib.sha256(task_id.encode()).digest()[0] % 3 == 0
