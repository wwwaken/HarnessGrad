## Can a host runtime be pinned?

**Yes, its userland can be pinned without moving scoring into Docker. The present ambient-host route is not pinned.** The narrowest correct mechanism is a **digest-addressed immutable native runtime closure**, mounted into the existing native verification namespace, with explicit executable paths and closed Python/native/child resolution. A venv, pip freeze, archive version, `ldd` list or pre-launch hash of mutable files is insufficient.

The closure must contain the exact interpreter and stdlib, site packages, ELF loader and every permitted native provider, child executable/JRE/JAR/LibreOffice module, plus dependency-affecting configs/resources/symlinks. It must fix or eliminate ambient PATH, Python/user-site/cwd shadowing, loader cache/search/preload, Java classpath/provider discovery, LibreOffice plugins/fonts and optional import selection. For the smaller BIRD/Chess graphs this can be much narrower than a whole host filesystem. For DS-1000 it must also define the candidate-visible runtime; arbitrary future native dependencies cannot be promised by a finite inventory of past imports. A previously unseen dependency must remain a refusal/unmeasured condition, without weakening an existing gate.

Trusted admission would verify the closure manifest and execute those **same immutable bytes** for the duration of the check. Read-only bind mounts of live host paths are not an immutable snapshot; hashing followed by execution of mutable paths leaves replacement/search/TOCTOU gaps. Content-addressed retained store objects or an immutable filesystem snapshot with the complete admitted userland can satisfy this, including a bundled loader and explicit library paths or a sealed namespace root without ambient fallback. A pinned image is another option, but is not necessary to establish a native userland pin. This determination proposes a mechanism only; no production implementation is changed or claimed.

The host kernel, vDSO, CPU ISA/features and numerical dispatch remain a separate compatibility/measurement envelope. They cannot all be frozen merely by hashing userland shared libraries. Record and validate that envelope independently; stronger full-machine reproducibility would require an explicitly pinned machine/VM/kernel arrangement. No such claim is made here.
