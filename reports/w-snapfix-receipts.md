# Snapshot identity and startup binding — w-snapfix

Expected snapshot identity is now enforced. The checker enters the committed filesystem without executing actor-controlled image startup first, apart from intentional platform inputs, Docker mounts and runtime-generated files. This closes the two demonstrated defects at this boundary; it does not establish a trusted checker runtime or complete snapshot/export integrity.

## Defect 1: separate expected identity and actual consumption comparison

`eval/containers/container_state.py:214` passes the commit return as the separately expected snapshot identity. `eval/verification/verifier.py:251` requires that value; missing/unpinned/mismatched values yield `passed=false`, `score=null`, `outcome=unmeasured` before creation. `eval/containers/container.py:760` retains `looks_pinned` syntax checks for both references and compares their digest components. After creation and before input copying/start, `require_snapshot_container` (`:767`, called at `verifier.py:307`) inspects Docker's actual `.Image` and compares it with the same expected identity. Inspection failure also refuses. The focused daemon-double control covers a substituted consumed identity separately from a substituted argument.

This authenticates consistency with the trusted host caller's retained commit identity, using the trusted local Docker daemon's content-address semantics. The normal caller does not obtain the expected value from an untrusted receipt or re-resolve a tag. It does **not** authenticate arbitrary expected values supplied by a lying caller, publisher provenance, signatures, historical layer custody, an honest daemon/host, or independently rehash production container bytes. `looks_pinned` remains a syntax check; the new equality is a distinct requirement.

## Defect 2: no actor startup before checker entry

`eval/containers/container.py:805` copies host BusyBox into a private temporary directory and validates that copy as a static ELF executable with neither PT_INTERP nor PT_DYNAMIC (`:779`). The verifier mounts that directory read-only at a fresh root-level path. Its explicit entrypoint invokes only BusyBox's idle sleep applet, with numeric duration 2147483647; `--no-healthcheck` prevents inherited health code and `--workdir /` avoids the image's startup directory (`:863`). The private mount lives through verifier teardown. Missing/dynamic host BusyBox fails unmeasured, with no actor-runtime fallback. The trusted host PATH/Binary/daemon are part of this trust boundary.

The former reward-directory `docker exec mkdir` is removed (`verifier.py:319`): Docker already mounts the fresh platform-created directory, and actor-owned mkdir could otherwise write before checker entry. There is now no snapshot executable between container creation and the checker invocation (`:326`). An absolute image `/bin/sleep` or a shell wrapper would be insufficient because its bytes, loader and preload inputs can be actor-controlled. A read-only root filesystem would break legitimate dependency installation; it is not imposed.

The actor lifecycle and its startup are untouched. Dependency/service networks, declared bridge attachment, recording mounts on the separate mounted-service route, fresh reward binds, limits and checker command/cwd/env/scoring remain. `scope-audit.json` verifies unchanged admission/stop/commit/looks_pinned functions, input copying, snapshot scoring, `_verify`, service code and pristine two-projection code. The full Option B suite passes, including service recording/network and pristine refusal controls.

## Exact registry observation - w-snapfix

Snapshot identity comparison and prevention of pre-check actor startup mutation are established for the container-state snapshot-service boundary at checker entry, under a trusted host/static BusyBox/local daemon. This is the exact new S3 snapshot-integrity sub-scope.
