## Execution and resolution binding

`eval/verification/native_runtime.py` hashes bytes *while copying* to memfds and applies write/grow/shrink/seal seals before exposing them to a scorer. Replacing the source after admission cannot alter those snapshots. Bubblewrap copies those sealed descriptors into read-only file mounts in an otherwise empty namespace root. This is stronger than hashing and then executing a mutable source path, or mounting a live host directory read-only. Admission closes every descriptor on success, error and timeout. No full host handling rewrite or Docker image is involved.

The manifest digest authenticates the resolution policy as well as the files: absolute interpreter/PT_INTERP paths; fixed `/lib/x86_64-linux-gnu:/lib64:/mnt/8t/xubuqiang/anaconda3/lib` library path; Python `-I -S -B`; fixed PATH/HOME/TMPDIR/LANG/LC_ALL; the admitted file destinations; and the exact trusted scorer/helper code. The loader launches explicitly with `--inhibit-cache`. The root contains no host `/usr`, `/etc/ld.so.cache`, preload config, site packages, user-site, Python caches or alternate hwcap providers. Their absence is enforced by the mount plan, not represented by invented file digests. Captured RPATH/DT_NEEDED/PT_INTERP bytes and the fixed, digest-bound manifest determine the remaining search. Collection-time `ldd` resolution is retained as evidence; verification never reruns `ldd` or consults its ambient graph.

Only `/task` is the read-only actor task mount and `/task/verifier` is reopened for verdict output; `/tmp`, `/proc`, `/dev` are private namespace facilities. Network is unshared, capabilities are dropped and the launcher dies with its parent. The check still reads the task-bound private input copies and actor SQL. Its trusted Python code is under `/scorer`, and helper imports resolve beside it (`data/datasets/bird_minidev/verify/check.py:36`). Consequently actor `random.py`, `sqlite3.py`, `PYTHONPATH`, `LD_PRELOAD` and `LD_LIBRARY_PATH` cannot select scorer code/providers. SQL `load_extension` remains disabled and scores as an invalid prediction under the existing EX semantics; it does not load a candidate library.
