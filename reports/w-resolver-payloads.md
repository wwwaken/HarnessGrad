## Which resolver inputs must be local

A finite `--no-index --find-links` wheel directory supplies candidate discovery. Each wheel supplies Name/Version, Requires-Dist, markers/extras, Requires-Python and WHEEL tags. Together with the target interpreter/platform and the roots/constraints, these are sufficient to resolve the demonstrated wheel-only graphs. **A PyPI Simple API mirror, versioned JSON response or opaque warm resolver cache is not required for this recipe.** The actual successful pip/uv logs show local wheel selection and transitive traversal. Saved PyPI JSON is evidence about acquisition, not a pip/uv-consumable index mirror and not a replacement for an absent wheel.

To reproduce this result locally, retain the resolver version, interpreter identity, target tags, every selected candidate's metadata and wheel bytes, exact roots/default extras, all transitive versions and hashes, and any direct-path/URL artifacts. Hash locks pin accepted artifacts; finite candidate directories and constraints prevent discovery of newer versions. An sdist instead requires its build-system metadata, build dependencies, compiler/OS inputs and an offline build closure; these experiments use only existing wheels and refuse sdists. Managed Python discovery/download is disabled for uv; its base interpreter is selected explicitly.

The native venv uses pip 24.0 / Python 3.12, observed in `raw/pip-version.stdout.txt` and `raw/native-runtime.json`. OpenSSL uses the retained uv 0.9.5 binaries and cached base's Python 3.13.7, observed in `tb3/uv-version.stdout.txt` and `tb3/runtime.json`. These fixture-relative raw paths are all under `tests/fixtures/hg_wresolver/`. This is the interpreter/ABI target of the experiment, not a new production lock.

Provisioning has three levels: original acquisition declarations; retained fixture/host payloads; adoption by production scoring. This work adds the second and demonstrates it. Native scoring still imports installed bytes, and Terminal-Bench's original apt/curl bootstrap still requires network. No adapter has been changed to adopt these finite recipes.

## Isolation, refusals and custody

No DNS or model address is queried.

The new OpenSSL container uses the inherited immutable cached image ID, `--pull=never --network=none --read-only --cpus=1 --memory=512m --pids-limit=64`, dropped capabilities, no-new-privileges, read-only input mounts and an executable bounded /tmp for the retained tool binaries. `raw/tb3-container-inspect.stdout.txt` records those settings, exit 0, no OOM, and no gateway/address. `tb3/network.json` records errno 101. uv compile and uvx use different absent cache directories; `--offline --no-index --no-python-downloads` is explicit. Tooling resolution does not attest the actor's snapshot, image publisher provenance or a complete image rebuild.

Negative controls remove a genuine transitive candidate: pip refuses missing py4j **despite its earlier installation in the venv**, because reconstruction ignores installed packages; uvx refuses missing pluggy with a fresh third cache. Raw failures are `raw/negative-missing-py4j.stderr.txt` and `tb3/negative-missing-pluggy.stderr.txt`. They are expected resolver refusals, not task scores.

All unsuccessful collection attempts remain: `raw/attempt1-terminal.txt` (empty-route header assumption before native resolution), `raw/tb-container.*` (unprivileged output mount permissions), `raw/tb2-container.*` (default noexec /tmp before uv invocation), and the initial inventory tracebacks (`raw/inventory*.stderr.txt`). Native/supplement venvs are removed with recorded cleanup; retained payload directories are deliberately preserved. These failures and the three real no-solution results are not zero scores.
